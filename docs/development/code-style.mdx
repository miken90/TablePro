# Code Style

## Tools

Enforced automatically — run before committing:

```powershell
npx eslint .          # from tablepro-windows/
cargo clippy --workspace --all-targets -- -D warnings   # from tablepro-windows/src-tauri/
```

`tablepro-windows/eslint.config.js` is the source of truth for frontend lint rules; there is no separate Prettier config or `rustfmt.toml` in this repo — `cargo fmt` defaults apply.

## File Naming

- Frontend (`src/`): kebab-case for `.ts`/`.tsx` files (e.g. `connection-form-sections.tsx`), matching existing convention
- Backend (`src-tauri/`): snake_case for `.rs` files, per standard Rust convention

## Project Structure

- Frontend state: Zustand stores in `src/stores/`, one store per domain (`connectionStore.ts`, `queryStore.ts`, `schemaStore.ts`, ...)
- Backend commands: `#[tauri::command]` handlers grouped by domain under `src-tauri/src/commands/`
- Drivers: each database engine is its own crate (`driver-postgres`, `driver-mysql`, ...) implementing the shared `DatabaseDriver` trait from `driver_trait.rs`

## Modularization

Split a file when it grows unwieldy rather than let it accumulate unrelated concerns — check existing sibling modules for the boundary convention before creating a new one (e.g. `commands/query.rs` vs `commands/query_streaming.rs`, `services/credential_store.rs` vs `services/credential_manager.rs`).

## i18n

User-facing strings go through `react-i18next` — add keys to both `src/i18n/locales/en.json` and `src/i18n/locales/vi.json` together, keeping them structurally in sync.
