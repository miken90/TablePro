# MongoDB Connections

TablePro connects to MongoDB via a compiled-in Rust driver (`mongodb`). Collections appear as tables in the sidebar. Documents display with fields as columns, and nested objects render as formatted JSON.

## Quick Setup

<Steps>
  <Step title="Create Connection">
    Click **New Connection**, select **MongoDB**, enter host/port/username/password/database, and click **Create**
  </Step>
  <Step title="Test Connection">
    Click **Test Connection** to verify
  </Step>
</Steps>

## Connection Settings

| Field | Default | Notes |
|-------|---------|-------|
| **Host** | `localhost` | |
| **Port** | `27017` | Disabled when **Use SRV** is on (resolved via DNS) |
| **Database** | - | Also used as the auth database — there is no separate auth-database field |
| **Username** | - | Leave empty for local dev without auth |
| **Password** | - | |
| **Use SRV** | off | Connect with `mongodb+srv://` instead of `mongodb://` |

## Example Configurations

**Local**: host `localhost:27017`, no auth, database `myapp`
**Docker**: host `localhost:27017` (or mapped port), password from `MONGO_INITDB_ROOT_PASSWORD` env
**MongoDB Atlas**: Turn on **Use SRV**
**Remote**: Use [SSH tunneling](/databases/ssh-tunneling) for secure access

## SSL/TLS

There is no SSL Mode selector for MongoDB. TLS is negotiated via the `mongodb+srv://` scheme (**Use SRV** toggle) or by pasting a connection string with TLS params into **Import from URL**. For unencrypted alternatives, use [SSH tunneling](/databases/ssh-tunneling).

## Features

**Collection Browsing**: Sidebar shows all collections. Click to view documents in data grid.

**Document Viewing**: Top-level fields as columns, nested objects as formatted JSON, arrays as JSON arrays, ObjectIds as strings, BSON types formatted appropriately. Schema inferred by sampling.

<Note>
MongoDB does not support DDL (Create Table / structure editing) or inline grid editing — the driver is read-only find().
</Note>

**Query command** (JSON, not MQL shell syntax): the query box sends a JSON object with `collection`, optional `filter`, optional `sort`, and optional `limit` (default 1000). It runs a single `find()` — no aggregation pipeline, no `countDocuments`/`distinct`, and no write operations (`insertOne`, `updateOne`, `deleteOne`, etc. are not implemented).

```json
{
  "collection": "users",
  "filter": { "age": { "$gte": 18 }, "active": true },
  "sort": { "date": -1 },
  "limit": 20
}
```

## Troubleshooting

**Connection refused**: Check the MongoDB service is running, verify host/port in `mongod.conf`, check `bindIp` setting.

**Auth failed**: Verify username/password and that the **Database** field matches an account with access there (it doubles as the auth database). Check user roles with `db.getUsers();` Create user with `db.createUser({user:"appuser", pwd:"password", roles:[{role:"readWrite", db:"myapp"}]})`

**Timeout**: Verify host/port, check network and firewall, whitelist IP in MongoDB Atlas.

**Limitations**: Read-only (`find()` only — no writes, no aggregation pipeline), schema inferred by sampling, GridFS not browsable, change streams unsupported.

**Performance**: Use `filter`, `limit`, and indexes in the query command.
