# Connection URL Reference

TablePro parses a connection URL when you click **Import from URL** on the New Connection form. This covers every supported scheme and what gets filled in.

## URL Schemes

| Scheme | Database |
|--------|----------|
| `postgresql://` | PostgreSQL |
| `postgres://` | PostgreSQL (alias) |
| `mysql://` | MySQL / MariaDB |
| `mssql://` | Microsoft SQL Server |
| `sqlserver://` | Microsoft SQL Server (alias) |
| `mongodb://` | MongoDB |
| `mongodb+srv://` | MongoDB (DNS SRV, turns on **Use SRV**) |
| `redis://` | Redis |
| `rediss://` | Redis (turns on **TLS / SSL**) |

Any other scheme — including `mariadb://`, `sqlite://`, and any database this fork doesn't ship — is rejected with "Unsupported protocol". SQLite has no URL form; it's a file path picked from the connection form.

There is no `+ssh` scheme and no query-parameter parsing (`sslmode`, `table`, `schema`, `authSource`, etc. are not read). The parser only fills host, port, username, password, and database.

## Format

```
scheme://[username[:password]@]host[:port][/database]
```

**Examples:**

```
postgresql://alice:secret@db.example.com:5432/myapp
mysql://root@localhost/shop
mongodb://user:pass@mongo.host:27017/analytics
mongodb+srv://user:pass@cluster.mongodb.net/analytics
redis://:password@cache.host:6379/1
rediss://:password@cache.host:6380
```

<Tip>
Username and password are percent-decoded from the URL, so a literal `@` in the password must be written as `%40`.
</Tip>

## What Gets Filled In

| Field | Source |
|-------|--------|
| **Type** | Mapped from the scheme (see table above) |
| **Host** | URL hostname, `localhost` if empty |
| **Port** | URL port, else the scheme's default (postgres 5432, mysql 3306, mssql 1433, mongodb 27017, redis 6379) |
| **Database** | URL path, without the leading `/` |
| **Username / Password** | From the URL's userinfo section |
| **Use SRV** (MongoDB) | On if the scheme is `mongodb+srv://` |
| **TLS / SSL** (Redis) | On if the scheme is `rediss://` |

SSH tunnel fields, SSL Mode, and startup commands are never set by URL import — configure them in the form after importing.

## Deep Links

TablePro registers the `tablepro://` scheme (not a database scheme) for two routes:

```
tablepro://open/connection/{connection-id}
tablepro://import?name=...&host=...&port=...&type=...&username=...&database=...
```

`open/connection/{id}` opens (and connects) a saved connection by its ID. `import` creates a new saved connection from the given fields — there's no `password` param, so the password is left blank and must be filled in manually afterward.
