# Connection Management

TablePro connects to 6 database engines. Create connections, organize them with colors, tags, and groups, and switch between them instantly.

## Supported Databases

Daily-driver engines for this fork: PostgreSQL, MySQL/MariaDB, SQLite.

## Creating a Connection

### From the Welcome Screen

The Welcome screen appears on first launch or when no connections are active.

1. Click **New Connection**
2. Fill in the connection details
3. Click **Test Connection** to verify
4. Click **Create** to save and connect

### From a Connection URL

Paste a connection string directly into the form:

1. Open the **New Connection** form
2. Click **Import from URL** in the General tab
3. Paste your connection URL into the dialog and click **Import**
4. All fields (type, host, port, database, username, password) are filled in automatically
5. Review the auto-filled values and click **Create**

See [Connection URL Reference](/databases/connection-urls) for all supported schemes and formats.

<Tip>
Connection URLs with special characters in the password (like `@`, `#`, or `%`) should use percent-encoding. For example, `p@ssword` becomes `p%40ssword`.
</Tip>

### Connection Form Fields

#### General Section

| Field | Description |
|-------|-------------|
| **Name** | A friendly name to identify this connection |
| **Type** | Database type: PostgreSQL, MySQL/MariaDB, SQL Server, SQLite, MongoDB, or Redis |

#### Appearance Section

| Field | Description |
|-------|-------------|
| **Color** | Color-code your connection for quick identification |
| **Tag** | Organize connections with a custom tag |
| **Group** | Assign connection to a group (folder) for organization |

<Tip>
Use colors to distinguish environments: red for production, green for development.
</Tip>

#### Connection Section

| Field | Description |
|-------|-------------|
| **Host** | Server address (default: `localhost`) |
| **Port** | Server port (auto-filled based on database type) |
| **Database** | Default database to connect to |

For SQLite, this section shows a file browser instead:

| Field | Description |
|-------|-------------|
| **File Path** | Path to the SQLite database file |

#### Authentication Section

For PostgreSQL, MySQL/MariaDB, SQL Server, MongoDB, and Redis:

| Field | Description |
|-------|-------------|
| **Username** | Database username |
| **Password** | Database password, DPAPI-encrypted at rest; optionally also mirrored into Windows Credential Manager |

<Note>
SQLite databases don't require authentication.
</Note>

#### SSL/TLS Section

For PostgreSQL, MySQL/MariaDB, and SQL Server connections, configure SSL/TLS encryption via **SSL Mode**. The form shows what the selected mode does, because the modes differ per engine: `require` encrypts without checking the server certificate on every engine, only the `verify-*` modes validate it, and SQL Server encrypts in every mode. See [PostgreSQL](/databases/postgresql#ssl-modes), [MySQL](/databases/mysql#ssltls) and [SQL Server](/databases/mssql#ssl-modes) for the per-engine tables.

MongoDB and Redis have their own TLS toggle (`tlsEnabled` for Redis; `mongodb+srv://` for MongoDB DNS-based TLS).

<Note>
SSL/TLS is not available for SQLite connections (file-based, no network involved).
</Note>

## Organizing Connections

Colors tint the toolbar when you connect (red for production, green for development). Tag and group connections in the sidebar.

Create connection groups by right-clicking in the connection list. Groups are a flat list (no subgroup nesting). Deleting a group ungroups its connections; it does not delete them.

## Quick Connection Switching

Switch connections from the toolbar:

1. Click the **connection name** button in the toolbar
2. A popover shows your active sessions and saved connections
3. Click any connection to switch immediately
4. Click **Manage Connections...** to open the full connection manager

## Switching Databases

To switch databases on the same connection:

1. Click the database name in the toolbar (next to the connection name)
2. Select a different database from the dropdown
3. The sidebar updates to show the new database's tables

No need to create separate connections for each database on the same server.

## Testing Connections

Before saving a connection, test it:

1. Fill in all required connection details
2. Click **Test Connection**
3. Wait for the result:
   - **Green checkmark**: Connection successful
   - **Red X**: Connection failed (see error message)

Most test failures are due to the server being down, wrong credentials, or network/firewall blocking the port.

## Reconnecting

When a connection drops, a **Reconnect** button appears in the toolbar. Click it to retry manually — reconnect is user-initiated, not automatic. For SSH connections, this also recreates the tunnel.

<Tip>
The toolbar status indicator shows connection state: connected, connecting, or error/disconnected.
</Tip>

## Startup Commands

SQL statements that run automatically on every connection. Use them to set session variables, timezone, encoding, or other session options.

Configure startup commands in the **Advanced** tab of the connection form. Enter one SQL statement per line.

### Common Examples

```sql
SET time_zone = '+00:00';
SET NAMES utf8mb4;
SET sql_mode = 'STRICT_TRANS_TABLES';
SET search_path TO myschema, public;
SET statement_timeout = '30s';
```

Sent to the driver as a single statement batch on connect. If it fails, a warning is logged and the connection still proceeds — nothing retries or rolls back.

<Note>
Startup commands run on every connection, including reconnects. They are database-specific: use MySQL syntax for MySQL connections, PostgreSQL syntax for PostgreSQL, and so on.
</Note>

## Editing and Deleting Connections

Right-click a connection to edit or delete it. Changes take effect on the next connection. Deleting removes the saved settings only; your database is unaffected.

## Storage

Connections are stored at `%APPDATA%\TablePro\connections.json` (and `groups.json` for connection groups). Passwords are DPAPI-encrypted at rest by default; enabling **Remember credentials in OS keychain** in Settings additionally mirrors them into Windows Credential Manager.
