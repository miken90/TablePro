# Safe Mode

Safe Mode is a global setting that controls how TablePro handles query execution before it reaches the database. The toolbar shows a level badge whenever Safe Mode is above **Off**; clicking it quick-cycles **Off → Alert → Read-Only → Off**. To reach **Silent**, **Alert+**, or **Safe Mode** specifically, set the level from Settings → Connection → Safe Mode instead.

## Levels

TablePro provides 6 levels:

| Level | Write Queries (INSERT/UPDATE) | Destructive Queries (DELETE/DROP/TRUNCATE/ALTER) |
|-------|-------------------------------|---------------------------------------------------|
| **Off** | Execute immediately | Execute immediately |
| **Silent** | Execute immediately | Execute immediately (logged to console) |
| **Alert** | Execute immediately | Confirmation dialog |
| **Alert+** | Confirmation dialog | Confirmation dialog |
| **Safe Mode** | Confirmation, must type table name | Confirmation, must type table name |
| **Read-Only** | Blocked entirely | Blocked entirely |

New installs default to **Alert**.

## How It Works

### Off

No checks at all.

### Silent

Destructive queries (`DELETE`, `DROP`, `TRUNCATE`, `ALTER`) are logged to the console but still execute immediately. No dialog.

### Alert

A confirmation dialog appears before executing destructive queries. Plain `INSERT`/`UPDATE` and read queries run without prompts.

### Alert+

Confirmation dialog for any DML (`INSERT`, `UPDATE`, `DELETE`) or destructive statement. Plain `SELECT` queries still run without prompts.

### Safe Mode

Same trigger as Alert+, but confirming requires typing the affected table's name into the dialog before the **Run Anyway** button is enabled.

### Read-Only

Any write statement (`INSERT`, `UPDATE`, `DELETE`, `DROP`, `TRUNCATE`, `ALTER`, `CREATE`) is blocked outright — no dialog, no override.

<Note>
Safe Mode covers the SQL editor, the MongoDB and Redis panels, the sidebar's **Truncate** / **Delete All Records** / **Drop** operations, and saving edited grid rows — all of them classify the statements they are about to run with the same check before executing. The visual table structure editor (column add/modify/drop) runs its own `ALTER TABLE` commands directly and is not classified by Safe Mode.
</Note>

<Note>
Safe Mode classification is regex-based on the SQL text (destructive: `DELETE|DROP|TRUNCATE|ALTER`; DML: `INSERT|UPDATE|DELETE`). It does not parse the query, so it can't distinguish schema-qualified statements or detect writes hidden inside stored procedure calls.
</Note>

The current level shows as a badge in the toolbar (hidden at Off); click it to quick-cycle Off → Alert → Read-Only → Off, or use Settings → Connection → Safe Mode to jump straight to any of the 6 levels.
