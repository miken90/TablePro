# Import & Export

Import `.sql`/`.sql.gz` files, export query or table results to CSV, JSON, SQL, or XLSX, and paste tabular data from the clipboard into the grid.

## Import a SQL File

Requires an active connection. Open the import dialog any of three ways:

- the **Import SQL** button (upload icon) on the main toolbar
- `Ctrl+Shift+M`
- the command palette (`Ctrl+Shift+P`) → **Import SQL**

Then:

1. Choose a `.sql` or `.sql.gz` file
2. Review the preview — file size, statement count, and the first statements found in the file
3. Set options: **Wrap in transaction (rollback on error)** (default on) and **Disable foreign key checks** (default off)
4. Run the import; progress is reported as statements execute

The schema tree refreshes when the import finishes, so tables created by the script appear without reconnecting.

While an import is running, the dialog cannot be dismissed — no backdrop click, no Escape. If the import fails partway through, the dialog stays open (it never auto-closes) and shows:

- the driver's error message
- how many statements ran before the failure — or, if no progress event ever arrived, an explicit "no progress reported" notice rather than claiming 0 statements ran
- whether the run can be trusted: with **Wrap in transaction** on, a note that a rollback was requested but completion can't be confirmed; with it off, a note that the statements that did run were committed

The retry action always re-runs the entire file — there is no resume point — so it's labeled **Re-run entire file** (with a warning) whenever the transaction option was off and some statements already committed, to flag the risk of duplicate writes.

<Note>
The toolbar button is hidden for engines that do not support import/export (MongoDB, Redis, and SQLite), which is the same capability check the export command enforces.
</Note>

## Export Data

1. Run a query or open a table (this produces a result in the grid)
2. Click **Export** on the results toolbar
3. Choose a format (CSV, JSON, SQL, or XLSX) and configure options
4. Click **Export**, choose a save location

The export re-runs the query that produced the grid, on the server, and writes
what comes back. How it reads depends on size:

- **Up to the "Store max rows" setting** (Settings → Performance, 100,000 by
  default): the result is read in one execution and written out. Memory is
  bounded by that setting.
- **Larger than that**: the export reads the rest in chunks, which is only
  correct when the query fixes its own row order. No engine here guarantees the
  same order across executions otherwise, so consecutive chunks would repeat
  some rows and skip others. A query with a top-level `ORDER BY` is paged; one
  without is **refused**, with a message asking for an `ORDER BY`.

A query that already ends in `LIMIT`/`OFFSET` (or SQL Server, which has no
`LIMIT` form) is always read in one execution — a pagination tail cannot be
appended to it.

<Tip>
If a large export is refused, add an `ORDER BY` on a column that uniquely
identifies each row — a primary key is ideal — or narrow the query with
`WHERE`.
</Tip>

### Export Formats

<Tabs>
  <Tab title="CSV">
    | Option | Default |
    |--------|---------|
    | Delimiter | `,` |
    | Include header row | Yes |

    NULL values are written as empty strings.
  </Tab>
  <Tab title="JSON">
    | Option | Default |
    |--------|---------|
    | Pretty print | No |
    | Array of arrays (instead of array of objects) | No |
  </Tab>
  <Tab title="SQL">
    | Option | Default |
    |--------|---------|
    | Table name (used in generated `INSERT` statements) | `export` |
    | Batch size (rows per `INSERT`) | 100 |
    | Include `CREATE TABLE` | No |

    Generates `INSERT INTO "table" (...) VALUES (...);` statements; string values are quoted and single quotes are escaped by doubling.
  </Tab>
  <Tab title="XLSX">
    An Excel workbook with a single sheet: one header row plus the result rows.

    Values that parse as a number are written as numeric cells; everything else is written as text. NULL is written as an empty string. Output is capped at Excel's sheet limit of 1,048,575 data rows, and cell text longer than 32,767 characters is truncated.

    XLSX has no text preview or **Copy** action in the dialog — it is a binary file, not text.
  </Tab>
</Tabs>

For the text formats (CSV, JSON, SQL) the dialog shows a live preview of the first 5 rows and offers a **Copy** action to copy the full export text without saving a file.

## Clipboard Paste (Tab-Separated)

Paste tabular data directly into the data grid. Select one or more rows, then press `Ctrl+V`. The clipboard text is split into lines, and each line into cells on tab characters — matching what the grid's own copy actions produce. There is no comma/CSV parsing: a comma-delimited clipboard is pasted as a single value per line. Each pasted line fills one selected row in order; primary-key columns are skipped, and empty values are written as NULL.
