# Import & Export

Import `.sql`/`.sql.gz` files, export query or table results to CSV, JSON, SQL, or XLSX, and paste tabular data from the clipboard into the grid.

## Import a SQL File

Requires an active connection. Open the import dialog any of three ways:

- the **Import SQL** button (upload icon) on the main toolbar
- `Ctrl+Shift+M`
- the command palette (`Ctrl+Shift+P`) → **Import SQL**

Then:

1. Choose a `.sql` or `.sql.gz` file
2. Review the preview — file size, statement count, and the first statements found in the file
3. Set options: **Wrap in transaction (rollback on error)** (default on) and **Disable foreign key checks** (default off)
4. Run the import; progress is reported as statements execute

The schema tree refreshes when the import finishes, so tables created by the script appear without reconnecting.

<Note>
The toolbar button is hidden for engines that do not support import/export (MongoDB and Redis), which is the same capability check the export command enforces.
</Note>

## Export Data

1. Run a query or open a table (this produces a result in the grid)
2. Click **Export** on the results toolbar
3. Choose a format (CSV, JSON, SQL, or XLSX) and configure options
4. Click **Export**, choose a save location

The export re-runs the query that produced the grid, on the server, and writes
what comes back. It runs **once**: the whole result is read into memory and
then written out. Paging the query in chunks was dropped because no engine here
guarantees the same row order across executions unless the query itself defines
one, so consecutive chunks could repeat some rows and skip others.

<Tip>
Use `LIMIT` in your query to control export size for large tables — a very
large result is held in memory before it reaches the file.
</Tip>

### Export Formats

<Tabs>
  <Tab title="CSV">
    | Option | Default |
    |--------|---------|
    | Delimiter | `,` |
    | Include header row | Yes |

    NULL values are written as empty strings.
  </Tab>
  <Tab title="JSON">
    | Option | Default |
    |--------|---------|
    | Pretty print | No |
    | Array of arrays (instead of array of objects) | No |
  </Tab>
  <Tab title="SQL">
    | Option | Default |
    |--------|---------|
    | Table name (used in generated `INSERT` statements) | `export` |
    | Batch size (rows per `INSERT`) | 100 |
    | Include `CREATE TABLE` | No |

    Generates `INSERT INTO "table" (...) VALUES (...);` statements; string values are quoted and single quotes are escaped by doubling.
  </Tab>
  <Tab title="XLSX">
    An Excel workbook with a single sheet: one header row plus the result rows.

    Values that parse as a number are written as numeric cells; everything else is written as text. NULL is written as an empty string. Output is capped at Excel's sheet limit of 1,048,575 data rows, and cell text longer than 32,767 characters is truncated.

    XLSX has no text preview or **Copy** action in the dialog — it is a binary file, not text.
  </Tab>
</Tabs>

For the text formats (CSV, JSON, SQL) the dialog shows a live preview of the first 5 rows and offers a **Copy** action to copy the full export text without saving a file.

## Clipboard Paste (CSV/TSV)

Paste tabular data directly into the data grid. Press `Ctrl+V` after selecting a row. Format is auto-detected: tabs parse as TSV, commas as CSV.
