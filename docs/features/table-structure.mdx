# Table Structure

Browse columns, indexes, foreign keys, and DDL for any table. Edit structure visually or with SQL.

Double-click a table in the sidebar, or right-click it and choose **View Structure**. The structure opens as its own tab beside your query and table tabs — the tab bar stays where it is — and it is restored on restart like any other tab; the schema is fetched when the tab is shown, not at launch. MongoDB and Redis connections offer no structure view.

## Columns Tab

| Property | Description |
|----------|-------------|
| **Name** | Column name — shows a key icon when it's the primary key |
| **Type** | Data type; click the cell to open the type picker |
| **Nullable** | Whether NULL values are allowed |
| **Default** | Editable here, but the panel doesn't display each column's existing default from the database — the fetch that populates this tab doesn't return it, so it starts blank for unmodified columns |

There's no "Extra" (e.g. `AUTO_INCREMENT`) or "Key" (PRI/FOR) column in this view.

## Indexes Tab

| Property | Description |
|----------|-------------|
| **Name** | Index name |
| **Columns** | Columns included in the index, comma-separated |
| **Unique** | `YES` / `NO` |
| **Type** | The index type as reported by the driver (e.g. BTREE, HASH) |

There's no "Primary" column in this view.

## Foreign Keys Tab

| Property | Description |
|----------|-------------|
| **Name** | Constraint name |
| **Column** | Local column(s) |
| **References** | Target table and column |
| **On Delete** | Action when referenced row is deleted |
| **On Update** | Action when referenced row is updated |

## DDL Tab

Shows the table's `CREATE TABLE` statement. Click **Copy DDL** in the top-right to copy it, or select the text manually. Useful for recreating tables, documenting schemas, or version control.

## Creating a New Table

Click **New Table** at the top of the sidebar (next to the search field). A dialog opens with:

- **Table name** field, and a **Schema** dropdown (only enabled for PostgreSQL — disabled for other engines)
- A **Columns** section — add rows with name, type (a dropdown of common types: INT, VARCHAR(255), TEXT, BOOLEAN, DATE, TIMESTAMP, DECIMAL(10,2), BIGINT, JSON, UUID), nullable, default value, and a primary-key checkbox
- A **DDL Preview** section — click **Generate Preview** to render the `CREATE TABLE` statement; it does not update live as you edit columns

Click **Create Table** to execute. The new table appears in the sidebar once the tree refreshes.

<Note>
There is no visual editor for indexes, foreign keys, storage engine, charset, or collation at table-creation time — add those afterward with SQL. There is no per-column comment field, and auto-increment has no control in this dialog even though the generated DDL supports it for a primary key when the driver requires it (e.g. SQLite `INTEGER PRIMARY KEY AUTOINCREMENT`, Postgres `SERIAL`/`BIGSERIAL`).
</Note>

<Note>
Supported databases: PostgreSQL, MySQL/MariaDB, SQL Server, SQLite. Each generates database-specific DDL syntax. MongoDB and Redis don't support DDL through this flow.
</Note>

## Modifying Structure

<Warning>
Structure modifications alter your database schema. Always backup important data before making changes.
</Warning>

### Visual Structure Editor

#### Adding Columns

1. Open the **Columns** tab, click **Add Column** at the bottom of the list
2. A new row appears (default name `new_column_N`, type `VARCHAR(255)`, nullable) — edit its name, type, nullable checkbox, and default value inline
3. Click the **Type** cell to open the type picker. Browse by category or search. For parametric types (`VARCHAR(255)`, `DECIMAL(10,2)`), type directly in the freeform field.
4. Click **Preview & Apply** in the pending-changes bar to review the generated SQL, then **Apply Changes** to execute

There is no primary-key, auto-increment, or comment field for a newly added column in this editor.

#### Modifying Columns

Edit a column's name, type, nullable checkbox, or default value inline in the row, then **Preview & Apply** to review and execute the `ALTER TABLE` SQL. Primary-key columns can't have their name or type changed here. There is no general undo/redo — only a staged drop can be reversed (see below) before you apply.

#### Removing Columns

Click the trash icon at the end of a column's row to stage it for removal — the row is struck through immediately, no confirmation prompt appears. Click **Undo** on that row to cancel the pending drop, or **Preview & Apply** to review and execute it along with any other staged changes.

### Schema Change Preview

Clicking **Preview & Apply** opens an **Apply Structure Changes** dialog listing the generated SQL statements (with a **Copy SQL** button); click **Apply Changes** to execute them, or **Cancel** to keep editing. Like the table-operation confirmations, initial focus is on Cancel, not Apply Changes.

<Note>
The visual queue-and-apply editor covers column add/modify/drop only. Indexes and foreign keys are managed by writing SQL directly (see below) — there is no visual add/edit/delete flow for them.
</Note>

### Adding Columns via SQL

```sql
-- MySQL
ALTER TABLE users ADD COLUMN phone VARCHAR(20) AFTER email;

-- PostgreSQL
ALTER TABLE users ADD COLUMN phone VARCHAR(20);

-- SQLite (limited ALTER TABLE)
ALTER TABLE users ADD COLUMN phone TEXT;
```

### Modifying Columns via SQL

```sql
-- MySQL
ALTER TABLE users MODIFY COLUMN name VARCHAR(200) NOT NULL;

-- PostgreSQL
ALTER TABLE users ALTER COLUMN name TYPE VARCHAR(200);
ALTER TABLE users ALTER COLUMN name SET NOT NULL;

-- SQLite (requires table recreation)
-- See SQLite documentation for workarounds
```

### Dropping Columns via SQL

```sql
-- MySQL/PostgreSQL
ALTER TABLE users DROP COLUMN phone;

-- SQLite (requires table recreation)
```

### Managing Indexes

```sql
-- Create index
CREATE INDEX idx_users_email ON users(email);

-- Create unique index
CREATE UNIQUE INDEX idx_users_username ON users(username);

-- Drop index
DROP INDEX idx_users_email ON users;  -- MySQL
DROP INDEX idx_users_email;  -- PostgreSQL
```

### Managing Foreign Keys

```sql
-- Add foreign key
ALTER TABLE orders
ADD CONSTRAINT fk_orders_user
FOREIGN KEY (user_id) REFERENCES users(id)
ON DELETE CASCADE;

-- Drop foreign key
ALTER TABLE orders DROP FOREIGN KEY fk_orders_user;  -- MySQL
ALTER TABLE orders DROP CONSTRAINT fk_orders_user;  -- PostgreSQL
```

## Refreshing Structure

Click the refresh icon in the sidebar header, or press `F5`. Changes made in TablePro refresh automatically.

## MongoDB Collections

MongoDB collections open in a dedicated MQL query tab rather than the table structure tab described above -- there is no structure/DDL view for MongoDB. See [MongoDB](/databases/mongodb) for querying details.
