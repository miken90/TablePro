# Change Tracking

Changes in TablePro are queued in memory, not applied immediately. Edit cells, insert rows, delete rows, then review everything before committing. Nothing touches the database until you say so.

<Tip>
Change tracking is per-tab. Switching tabs preserves your edits.
</Tip>

## Data Changes

TablePro tracks three types of data changes: cell edits, row insertions, and row deletions.

### Editing Cells

To edit an existing cell:

1. Double-click the cell
2. Enter the new value
3. Press `Enter` to confirm or `Escape` to cancel

<Note>
Changing a value back to its original automatically removes it from the queue.
</Note>

### Adding Rows

To insert a new row:

1. Click the **+** button in the toolbar or use the keyboard shortcut
2. A new row appears at the bottom of the data grid, marked with an insertion indicator
3. Fill in the values for each column
4. Columns with default values are pre-filled with `DEFAULT`

Edits to cells in a new row are folded into the insertion, not tracked as separate updates.

### Deleting Rows

To delete rows:

1. Select one or more rows in the data grid
2. Press the `Delete` key or click the delete button
3. Deleted rows are marked with a strikethrough indicator

Deleted rows stay visible until you commit or discard.

<Warning>
Batch deletion of multiple rows is tracked as a single undo action. Undoing a batch deletion restores all rows at once.
</Warning>

## Commit & Discard

### Committing Changes

Click **Commit** or press `Ctrl+S`. TablePro generates SQL with values inlined as escaped literals (not parameterized placeholders), executes one statement per changed row, clears the queue, and refreshes the grid.

Generated SQL shape:

| Change Type | SQL Generated |
|-------------|--------------|
| Cell edit | `UPDATE ... SET col='value' WHERE pk=1;` |
| Row insertion | `INSERT INTO ... (columns) VALUES ('value', ...);` |
| Row deletion | `DELETE FROM ... WHERE pk=1` (one statement per row) |

<Note>
If a table has no primary key, both UPDATE and DELETE statements fall back to matching on all column values instead of erroring.
</Note>

### Discarding Changes

Click **Discard** to revert all pending changes. Modified cells return to their original values, inserted rows are removed, and deleted rows are unmarked. This also clears the undo/redo stack.

### Previewing Data SQL

Click **Preview SQL** in the pending-changes strip to see the statements before committing, and **Copy** to put them on the clipboard.

The statements come from the backend's `preview_statements` command, which shares its generation path with the save itself — the preview shows the identifiers quoted for your engine, the values quoted by their declared column type, and the transaction wrapper only when the save will actually open one. The execute confirmation shows the same plan, and its Execute button stays disabled until the plan has loaded.

## Undo & Redo

| Action | Shortcut |
|--------|----------|
| Undo | `Ctrl+Z` |
| Redo | `Ctrl+Y` or `Ctrl+Shift+Z` |

<Tip>
Context-aware: `Ctrl+Z` undoes text edits when the SQL editor is focused, data changes when the grid is focused.
</Tip>

Stacks are per-tab. Committing or discarding clears both stacks.

## Schema Changes

Column changes in the Structure tab use the same queue-based approach.

### Tracked Schema Operations

| Operation | What Is Tracked |
|-----------|----------------|
| **Add column** | New column definition (name, type, nullable, default) |
| **Modify column** | Old and new column definitions |
| **Delete column** | Column marked for removal |

<Note>
Indexes, foreign keys, and primary keys are not tracked through this queue — only column add/modify/drop generate ALTER TABLE statements this way.
</Note>

### Visual Indicators

- **New items**: highlighted with an insertion color
- **Modified items**: changed fields are marked
- **Deleted items**: shown with a deletion indicator

## Previewing Schema SQL

Before applying schema changes, preview the generated SQL:

<Steps>
  <Step title="Make Changes">
    Add, modify, or delete columns, indexes, or foreign keys in the Structure tab
  </Step>
  <Step title="Click Commit">
    Click the Commit button or press `Ctrl+S`
  </Step>
  <Step title="Review SQL">
    A preview sheet shows all ALTER TABLE statements that will execute
  </Step>
  <Step title="Apply or Cancel">
    Click **Apply Changes** to execute, or **Cancel** to go back and adjust
  </Step>
</Steps>

<Tip>
Copy individual SQL statements from the preview sheet using the copy button next to each statement.
</Tip>

## SQL Generation

Data changes use identifier quoting and value literals appropriate to the connection's dialect — no bind parameters:

<Tabs>
  <Tab title="MySQL/MariaDB">
    ```sql
    UPDATE `users` SET `name`='Alice' WHERE `id`=1;
    INSERT INTO `users` (`name`, `email`) VALUES ('Alice', 'a@example.com');
    DELETE FROM `users` WHERE `id`=1
    ```
  </Tab>
  <Tab title="PostgreSQL / SQLite">
    ```sql
    UPDATE "users" SET "name"='Alice' WHERE "id"=1;
    INSERT INTO "users" ("name", "email") VALUES ('Alice', 'a@example.com');
    DELETE FROM "users" WHERE "id"=1
    ```
  </Tab>
  <Tab title="SQL Server">
    ```sql
    UPDATE [users] SET [name]='Alice' WHERE [id]=1;
    INSERT INTO [users] ([name], [email]) VALUES ('Alice', 'a@example.com');
    DELETE FROM [users] WHERE [id]=1
    ```
  </Tab>
</Tabs>
