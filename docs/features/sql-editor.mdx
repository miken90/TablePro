# SQL Editor

Write and run SQL with tree-sitter-powered syntax highlighting, schema-aware autocomplete, and multi-statement execution in a single editor pane.

## Editor Features

### Syntax Highlighting

Real-time syntax highlighting covers:

- **Keywords**: `SELECT`, `FROM`, `WHERE`, `JOIN`, etc. (pink)
- **Strings**: Single and double-quoted strings (green)
- **Numbers**: Numeric literals (blue)
- **Comments**: Single-line (`--`) and multi-line (`/* */`) comments (gray)
- **Functions**: Built-in SQL functions
- **Identifiers**: Table and column names

### Line Numbers

Line numbers are on by default. Useful for:

- Matching error messages to specific lines
- Navigating large queries
- Referencing code in conversations

<Tip>
Toggle line numbers in **Settings** > **Editor** > **Show Line Numbers**.
</Tip>

### Current Line Highlighting

The current line gets a subtle highlight so you can track your cursor position in long queries.

### Active Statement Highlighting

When your cursor is inside a SQL statement, that entire statement gets a subtle background highlight and left border. This shows you exactly which statement `Ctrl+Enter` would execute — helpful when you have multiple statements in one editor tab.

### Code Folding

Fold and unfold code blocks to manage long queries. A fold gutter appears in the left margin for foldable regions:

- `BEGIN` / `END` blocks
- `CASE` expressions
- Subqueries in parentheses
- Block comments (`/* ... */`)

Use `Ctrl+Shift+[` to fold and `Ctrl+Shift+]` to unfold at the cursor.

## Writing Queries

### Single Query

Write and execute a single query:

```sql
SELECT * FROM users WHERE active = true;
```

Press `Ctrl+Enter` to execute.

### Multiple Queries

Separate multiple queries with semicolons:

```sql
SELECT * FROM users LIMIT 10;
SELECT COUNT(*) FROM orders;
SELECT name, email FROM customers WHERE country = 'US';
```

Place your cursor in any statement and press `Ctrl+Enter` to execute just that one.

### Selecting and Executing

Select text and press `Ctrl+Enter` to run only the selection.

If the selection contains **multiple statements** (separated by semicolons), they run sequentially in a transaction:

- Statements execute in order, one at a time
- If any statement fails, execution stops and all changes roll back
- The error message identifies which statement failed (e.g. "Statement 3/5 failed: ...")
- Results from the last `SELECT` are shown in the data grid
- Each statement is recorded individually in query history

Good for running SQL dumps, migrations, or batches of related statements:

```sql
DROP TABLE IF EXISTS users;
CREATE TABLE users (id INT PRIMARY KEY, name VARCHAR(100));
INSERT INTO users VALUES (1, 'Alice'), (2, 'Bob');
SELECT * FROM users;
```

## Autocomplete

Schema-aware SQL autocomplete that adapts to your query context.

### Triggering Autocomplete

Autocomplete appears automatically as you type. You can also:

- Start typing a keyword, table name, or column name
- Press `Escape` to dismiss the popup
- Use arrow keys to navigate suggestions
- Press `Enter` or `Tab` to accept a suggestion

### What Gets Suggested

| Context | Suggestions |
|---------|-------------|
| After `SELECT` | Column names, `*`, functions |
| After `FROM` | Table names, schema names |
| After `JOIN` | Table names |
| After `WHERE` | Column names from selected tables |
| After `.` (dot) | Columns from the specified table |
| Start of statement | SQL keywords |

### Schema-Aware Completion

Autocomplete resolves table aliases and shows the right columns:

```sql
SELECT u.  -- Shows columns from 'users' table aliased as 'u'
FROM users u
JOIN orders o ON u.id = o.  -- Shows columns from 'orders' table
```

### SQL Keywords

Keywords are suggested based on context:

- After `SELECT`: `DISTINCT`, `TOP`, `ALL`
- After `FROM`: `JOIN`, `LEFT JOIN`, `INNER JOIN`, `WHERE`
- After `WHERE`: `AND`, `OR`, `NOT`, `IN`, `LIKE`, `BETWEEN`

## Query Execution

### Running Queries

| Action | Shortcut | Description |
|--------|----------|-------------|
| Execute query | `Ctrl+Enter` | Runs query at cursor, or all selected statements |
| Explain query | `Ctrl+Shift+X` | Show the execution plan for the query at cursor |
| Format query | `Ctrl+Shift+F` | Format the current query for readability |

### Query Results

Results appear in the data grid below the editor:

- Row count and execution time are shown
- Results are paginated for large datasets
- Click column headers to sort

### Status Bar

A persistent status bar at the bottom of the window shows:

**Left side (Connection & Schema Info):**
- **Connection status** — connected/disconnected indicator
- **Driver badge** — which database driver is active (e.g. PostgreSQL, MySQL)
- **Database name** — currently selected database
- **Table count** — number of tables in the current database

**Center (Query Results):**
- **Row count** — number of rows returned by the last query or rows affected by INSERT/UPDATE/DELETE
- **Execution time** — query duration in milliseconds

**Right side (Panel Toggles):**
- **Inspector button** — click to show/hide the cell inspector panel (or press `Ctrl+Shift+I`)
- **Filter button** — click to show/hide the filter panel

### Explain Query

View the execution plan for your query to spot missing indexes or inefficient joins.

To explain a query:

- Click the **Explain** button in the editor toolbar, or
- Press `Ctrl+Shift+X`, or
- Use the menu: **Query** > **Explain Query**

TablePro automatically uses the correct syntax for your database:

| Database | Syntax Used |
|----------|-------------|
| MySQL / MariaDB | `EXPLAIN <query>` |
| PostgreSQL | `EXPLAIN <query>` |
| SQLite | `EXPLAIN QUERY PLAN <query>` |

The execution plan shows index usage, join strategies, and estimated row counts in the data grid.

<Tip>
Run Explain before executing expensive queries to verify they use the expected indexes and join strategies.
</Tip>

## SQL Formatting

Built-in SQL formatter that restructures queries for readability. Dialect-aware: it adapts output to MySQL, PostgreSQL, or SQLite syntax.

### Format Query

To format the current query:

- Press `Ctrl+Shift+F`, or
- Click the **Format** button in the editor toolbar, or
- Use the menu: **Query** > **Format Query**

The formatter applies these transformations:

| Transformation | Description |
|----------------|-------------|
| **Keyword capitalization** | SQL keywords are uppercased (`select` becomes `SELECT`) |
| **Smart indentation** | Clauses are indented logically with consistent spacing |
| **Line breaks** | Each major clause (`SELECT`, `FROM`, `WHERE`, `JOIN`, etc.) starts on a new line |
| **Cursor preservation** | Your cursor position is preserved after formatting |
| **Comment preservation** | Single-line (`--`) and multi-line (`/* */`) comments are kept intact |
| **String preservation** | String literals are never modified |

### Dialect-Aware Formatting

The formatter detects your connected database and applies dialect-specific rules:

| Database | Formatting Behavior |
|----------|---------------------|
| MySQL / MariaDB | Backtick-quoted identifiers preserved, MySQL-specific syntax handled |
| PostgreSQL | Double-quoted identifiers preserved, PostgreSQL-specific syntax handled |
| SQLite | SQLite-specific keywords and syntax handled |

### Before & After Example

**Before** (unformatted):

```sql
select u.id,u.name,u.email,count(o.id) as order_count from users u left join orders o on u.id=o.user_id where u.created_at>'2024-01-01' and u.status='active' group by u.id,u.name,u.email having count(o.id)>5 order by order_count desc limit 100;
```

**After** (`Ctrl+Shift+F`):

```sql
SELECT
    u.id,
    u.name,
    u.email,
    COUNT(o.id) AS order_count
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE u.created_at > '2024-01-01'
    AND u.status = 'active'
GROUP BY u.id, u.name, u.email
HAVING COUNT(o.id) > 5
ORDER BY order_count DESC
LIMIT 100;
```

<Tip>
Format queries before sharing with teammates or saving as templates for consistent, readable SQL.
</Tip>

### Error Handling

When a query fails:

1. The error message appears below the editor
2. A wavy red underline marks the error position in the SQL text (PostgreSQL: character offset, MySQL: line number)
3. The error marker clears automatically when you edit the query or run a new one

## Vim Mode

Optional Vim keybindings for modal editing. Normal, Insert, Visual, and Command-line modes are all supported.

### Enabling Vim Mode

Toggle in **Settings** > **Editor** > **Editing** > **Vim mode**. A mode indicator badge appears in the editor toolbar when active.

### Modes

| Mode | Description |
|------|-------------|
| **Normal** | Default mode for navigation and commands. Press `Escape` to return here. |
| **Insert** | Text input mode, behaves like a standard editor. |
| **Visual** | Character-wise selection mode. |
| **Visual Line** | Line-wise selection mode. |
| **Command-line** | Ex commands (`:w`, `:q`, etc.). |

### Motions

| Key | Action |
|-----|--------|
| `h` / `j` / `k` / `l` | Left / Down / Up / Right |
| `w` / `b` / `e` | Next word / Previous word / End of word |
| `0` / `$` | Beginning / End of line |
| `gg` / `G` | First line / Last line |

### Operators

| Key | Action |
|-----|--------|
| `dd` | Delete line |
| `yy` | Yank (copy) line |
| `cc` | Change line |
| `x` | Delete character |
| `p` / `P` | Paste after / Paste before |
| `d` + motion | Delete with motion (e.g., `dw`, `d$`) |
| `y` + motion | Yank with motion (e.g., `yw`, `y0`) |
| `c` + motion | Change with motion (e.g., `cw`, `c$`) |

### Entering Insert Mode

| Key | Action |
|-----|--------|
| `i` / `I` | Insert before cursor / Insert at line start |
| `a` / `A` | Append after cursor / Append at line end |
| `o` / `O` | Open line below / Open line above |

### Visual Mode

Press `v` for character-wise or `V` for line-wise visual selection. Use motions to extend the selection, then apply an operator:

- `d` — delete selection
- `y` — yank selection
- `c` — change selection

### Command-Line Mode

Press `:` in Normal mode to enter command-line mode:

| Command | Action |
|---------|--------|
| `:w` | Execute the current query (equivalent to `Ctrl+Enter`) |
| `:q` | Close the current tab |

### Count Prefixes

Most motions and operators accept a count prefix: `3j` moves down 3 lines, `2dd` deletes 2 lines, `5x` deletes 5 characters.

### Escape Coordination

With Vim mode enabled, `Escape` returns to Normal mode. If AI autocomplete suggestions are visible, the first `Escape` dismisses the suggestion and the second returns to Normal mode.

<Tip>
The mode indicator badge in the toolbar shows your current Vim mode (NORMAL, INSERT, VISUAL) so you always know which mode you are in.
</Tip>

## Tips and Tricks

### AI Assistance

See [AI Chat](/features/ai-chat) for writing and debugging queries with AI.

### Using Comments

Add comments to document your queries:

```sql
-- Get active users with recent orders
SELECT u.name, COUNT(o.id) as orders
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE u.active = true
    AND o.created_at > CURRENT_DATE - INTERVAL '30 days'
GROUP BY u.name;

/*
 * Multi-line comment
 * Useful for longer explanations
 */
```

### Quick Table Exploration

Quickly check a table's structure and data:

```sql
-- View table structure (MySQL)
DESCRIBE users;

-- View table structure (PostgreSQL)
\d users

-- Sample data
SELECT * FROM users LIMIT 10;

-- Row count
SELECT COUNT(*) FROM users;
```

### Using Aliases

Table aliases keep queries cleaner and shorter:

```sql
-- Without aliases (verbose)
SELECT users.name, orders.total
FROM users
JOIN orders ON users.id = orders.user_id;

-- With aliases (cleaner)
SELECT u.name, o.total
FROM users u
JOIN orders o ON u.id = o.user_id;
```

## Best Practices

### Always Use LIMIT

When exploring data, always add `LIMIT` to avoid loading millions of rows:

```sql
SELECT * FROM large_table LIMIT 100;
```

### Test DELETE/UPDATE with SELECT First

Before running destructive queries, verify with SELECT:

```sql
-- First, verify what will be affected
SELECT * FROM users WHERE last_login < '2023-01-01';

-- Then run the actual delete
DELETE FROM users WHERE last_login < '2023-01-01';
```

### Use Transactions for Safety

Wrap dangerous operations in transactions:

```sql
BEGIN;

DELETE FROM important_table WHERE condition;

-- Verify the results
SELECT COUNT(*) FROM important_table;

-- If correct:
COMMIT;

-- If wrong:
ROLLBACK;
```
